## Bugs found (with fix where it was mine to make)
1. (L1, interaction) F_SETLKW interrupted by a signal (EINTR) left `fscred.lockwait` set; a process that then waited on the interrupted one got a false EDEADLK. Repro: ktest "...and the interrupted wait leaves no trace" (holder exit 3 = EDEADLK). Fix: kernel/fs_sys.c `deadlock()` follows a waiter only if `procs[p].nsys == fscred[p].lockwait_nsys`; new field in kernel/kernel.h.
2. (L1, interaction) spawn and execve always said ENOENT when the walk failed; a symlink loop gave ENOENT, not ELOOP. Repro: `forktest x-exec /tmp/ix/loop1` gave 102. Fix: `vfs_lookup_err()` in kernel/vfs.c, used by proc_spawn and sys_execve.
3. (L1, vfs, level 2 only) `open("/dev/ptmx")` creates /dev/pts/N with the caller's credentials: uid 1000 cannot create it in root's /dev/pts. Fix: `vfs_mkdev` uses fsuid/fsgid 0 and the real root while it runs.
4. (L1, choice) exec must not call `vfs_proc_start` (it bumps the lock generation; POSIX keeps record locks across exec). Added `vfs_proc_exec()`. Checks: "execve keeps the process's record locks (POSIX)", "...but closing a close-on-exec descriptor of the file at exec drops them".
5. (L2, cc's ld) the trap stub of an undefined weak function had body `{3, 0, 0, 0x0b}` (3 local groups declared). Since fork's crt0 refers weakly to `__fork_main`, every program linked by our ld failed to compile ("local decls count bigger than remaining function size"): cc suite 15/36. Fix: `{0, 0, 0x0b}` in bin/ld/ld.c: 36/36 with our ld and wasm-ld.
6. (L2, libpkg) symlink times were not restored. Fix: `utimensat(..., is_link ? AT_SYMLINK_NOFOLLOW : 0)` in libpkg/dpkg.c apply_meta (dpkg uses lutimes). After it, 545 of 545 compared paths have the tar's mtime.
7. (L2, interaction, NOT fixed: authors' choice) /debian now always exists (pkg ships rootfs/debian/etc/apt/sources.list), so lx's default root is /debian and the documented M2 command fails ("not found"); passes with `--root=/`. And dpkg.cfg's example `script-runner /bin/ENGINE --root %r` (substitutes %r only as a whole word) vs lx accepting only `--root=DIR`: `lx: unknown option --root`. `script-runner /bin/lx` works because of the /debian default.
8. (L3, open) after the scripts ran under the engine, /debian/etc/shells has `/sh`, `/bash`, `/dash`, `/rbash` where Debian has `/usr/bin/sh` and so on: update-shells' `$(dpkg-realpath --root "$ROOT" "$(dirname "$line")")` printed nothing during the debianutils trigger. Run by hand under the engine (same root, `env -i` with libpkg's exact environment, cwd /debian, empty --root), dpkg-realpath prints `/usr/bin` every time. Not traced further.
9. (L3, sh stream) the shell's `wait PID` returns a finished earlier job's status when the pid number is reused (UC.OS reuses pids at once): `sh -c 'sleep 5 & p=$!; kill -INT $p; wait $p; echo $?; sleep 5 & p=$!; kill -TERM $p; wait $p; echo $?'` prints 130 twice; the TERM case alone prints 143. In interactive use: `sleep 5 &`, `kill $!`, `wait $!` says "pid 2 is not a child of this shell", status 127.
10. (L3, engine) when the kernel answers ENOSYS to pclone, the -DLX_HAVE_PCLONE engine falls back to the emulated fork silently: a stale kernel.wasm (built before the renumbering) gave identical results for both builds until traced with --trace (wait4 returned 100000, the emulated pids).
